## 3. Critical Bugs & Traps Identified by User (READ CAREFULLY)

When preparing the TPU pretraining run, the user identified two critical pitfalls that must be respected:

### ⚠️ Trap 1: Kaggle "Script" vs "Notebook" Kernel Type (Showstopper)
* **The Bug:** In Kaggle, if you create a kernel as a **Python Script** (`/script`), it treats the file as raw Python code. Pasting or writing `.ipynb` JSON into a Script kernel causes Python to execute `python script.py` directly on the file, crashing immediately on line 18 with:
  ```text
  NameError: name 'true' is not defined
  ```
  Even without that syntax error, Python would simply evaluate an in-memory dictionary in 0.2 seconds and terminate without ever executing code cells, shell commands (`!git clone`, `!pip install`), or training loops.
* **The Required Action:**
  1. Any previous queued Script runs (e.g. ScriptVersionId `368098383`) must be cancelled.
  2. The kernel MUST be created as an actual **Jupyter Notebook** (`/code/.../notebook` with individual runnable code and markdown cells).
  3. Upload `TinyTransformer_Kaggle_TPU_v5e_8.ipynb` via **File $\rightarrow$ Upload Notebook** so Kaggle properly parses the JSON into real runnable cells.

### ⚠️ Trap 2: Fallback Targets in Cells 4A & 4B (Data Starvation)
* **The Bug:** If the pre-tokenized dataset mount check failed or fell through, Cells 4A and 4B previously had default fallback targets of 1.85B and 150M tokens. In an 8.4-hour run on TPU v5e-8 consuming ~3.8B tokens, this would cause data starvation and an unexpected EOF/IndexError around Hour 4.
* **The Fix:**
  * Updated in [`TinyTransformer_Kaggle_TPU_v5e_8.ipynb`](file:///d:/TinyTransformer/TinyTransformer_Kaggle_TPU_v5e_8.ipynb#L197):
    * Cell 4A: `FOUNDATION_TARGET_TOKENS = 3_600_000_000`
    * Cell 4B: `INSTRUCT_TARGET_TOKENS = 200_000_000`
  * Committed in Git commit `f21b546`.

### ⚠️ Trap 3: Window Isolation Rule
* **Rule:** The user has two Chrome windows open.
  * **Window 1:** Contains Kaggle (where work must be done).
  * **Window 2:** Contains Google / Gemini (DO NOT TOUCH, DO NOT CLOSE, DO NOT INTERACT WITH).

## 4. TPU v5e-8 Training Setup Checklist

When launching the training run in the new session:

1. **Notebook Source:** `D:\TinyTransformer\TinyTransformer_Kaggle_TPU_v5e_8.ipynb`.
2. **Kaggle Mode:** **Notebook** (Not Script).
3. **Hardware Settings (Session Options):**
   * **Accelerator:** `TPU VM v5e-8` (8 cores, 128 GB Total HBM).
   * **Internet:** `ON` (`checked: true`).
4. **Input Data (+ Add Input):**
   * Attach `tinytransformer-shards-3-8b` (or attach the output of `TinyTransformer-Data-Sharding`).
5. **Execution Command in Step 5:**
   ```bash
   !python -u train.py \
       --tpu-cores 8 \
       --batch-size 4 \
       --grad-accum 1 \
       --dtype bfloat16 \
       --base-hours 7.8 \
       --max-hours 8.4 \
       --checkpoint-dir /kaggle/working/checkpoints \
       --log-dir /kaggle/working/logs \
       --shard-dir /kaggle/working/TinyTransformer/data/shards \
       --save-interval 250 \
       --infer-interval 12500 \
       --resume
   ```
   * **Global Batch Size:** $4 \times 1 \times 8 \times 1024 = \mathbf{32,768 \text{ tokens/step}}$.
   * **Hours 0.0 – 7.8:** 3.6B unique foundation tokens (**1.0 unique epoch = 100% Pareto efficiency & maximum Engram hash entropy**).
   * **Hours 7.8 – 8.4:** Instruct annealing mix on 200M tokens (tool-use, CoT, coding).
   * **Hour 8.4:** Graceful shutdown code 0 before Kaggle's 9.0h hard limit.
   * **Mini-Inference Previews:** `--infer-interval 12500` fires once every ~50 minutes (~10 times total in 8.4h).
6. **Headless Execution:** Trigger via **Save Version $\rightarrow$ Save & Run All (Commit)** with title `'TPU v5e-8 Pretrain (3.8B SOTA 1.0 Epoch)'`. This guarantees server-side execution so the user can close their laptop.
